# 路线图

> 路线图是公开优先级与验收思路，不是发布日期、商业承诺或维护者 SLA。最后更新：2026-11-06。v0.2.0 已完成从 `b4ea7f4`（2024-08-18）到 Vite 6、本地演示数据与测试基线的现代化。

## 0. 当前判断

兰泽诗词最有价值的部分是已经存在的中文诗词界面、素材和完整 `git` 历史。v0.2.0 已解决旧构建工具、硬编码业务服务、没有测试与没有明确边界等主要参与门槛；接下来的重点是体积、交互回归、素材授权和可选后端契约。

优先级原则：

1. 不破坏原有视觉与路由骨架。
2. 每轮改动都能通过 `npm ci && npm run build && npm run test && npm run lint` 验证。
3. 文档、CI、代码现代化同步；不宣传未验证的线上服务。
4. 私密凭据、第三方素材授权与用户数据问题优先于新页面。

## 1. v0.2.0 — 本地可运行的开源前端（已完成）

状态：已合并代码、文档、CI 与发布素材；本地 `npm ci`、build、14 项单测与 lint 均通过。Release / Discussion 由仓库发布工作流维护。

GitHub 侧配合：维护 About、topics、社交预览图；发布 `v0.2.0` Release 与 Discussions 欢迎帖；按需手动触发 Pages 并验证站点。详见 `docs/PROMOTION.md`、`RELEASE_NOTES.md`、`ANNOUNCEMENT.md`。

| 优先级 | 事项 | 为什么 | 验收标准 |

## 4. v0.5.x — 可选后端与社区协作

- 只有当维护者确认边界后，才增加示例 API / Docker Compose / 账号与创作持久化；保持前端仓库独立运行。
- 讨论隐私说明、数据导出与关闭线上服务的方式；不把演示账号系统当生产认证。
- 建立贡献者名录、定期议题与可视化维护记录，但不设置增长目标或 SLA。

## 5. v1.0 之后 — 社区化（条件性）

只有在工程优化、E2E、错误态与素材授权问题稳定后，才考虑：

- 公开且被维护者验证的静态前端 Demo（仅演示数据，不收集账号）；
- 可插拔后端、账号与创作持久化，带隐私说明与数据导出；
- 完整中英文 i18n、主题与阅读偏好；
- Discussions 定期议题、贡献者名录、Release 自动化、可视化仪表盘；
- 与其他中文开源诗词语料/工具的可授权集成。

任何一个「线上」能力都必须先回答：谁托管、谁维护、数据从哪来、如何关闭、如何回滚、出问题向谁报告。没有答案就不写进 README 的特性承诺。

## 6. 明确不做的事

- 不恢复旧 MemFire/Vercel 展示地址为官方 Demo。
- 不在没有授权审查前把第三方音乐/字体/诗词全文宣称为 MIT 内容。
- 不为了 star 数、曝光或版本号制造虚假数据、刷量或夸大功能。
- 不把本仓库变成需要付费/私密基础设施才能运行的项目。
- 不把 GitHub 发布、Pages 或外部宣发写成未经核对的事实。

## 7. 每次迭代的 Definition of Done

- [ ] 改动范围写入 `CHANGELOG.md` 的对应版本或 `Unreleased`。
- [ ] `README.md`、`docs/DEVELOPMENT.md`、`docs/DEPLOYMENT.md` 与实际脚本/变量一致。
- [ ] CI 在 Node 20/22 执行 `npm ci`、build、测试与文档检查。
- [ ] 无新增硬编码密钥、真实用户数据或失效线上承诺。
- [ ] 至少一条手动 QA 路径被记录；失败路径也有说明。
- [ ] 若发布，Release notes 只描述已合并并验证的内容。
