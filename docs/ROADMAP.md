# 路线图

> 路线图是公开优先级与验收思路，不是发布日期、商业承诺或维护者 SLA。最后更新：2026-11-07。v0.2.0 完成现代化；v0.3.0 完成视图层重构；v0.4.0 整理离线馆藏、移动端体验与本地声景曲库。

## 0. 当前判断

兰泽诗词最有价值的部分是中文诗词内容、素材和完整 `git` 历史。当前 `main` 已把界面收敛到「一首诗一展厅」的六页面结构，移除旧 UI 套件与占位栏目；接下来的重点是视觉回归、素材授权、内容依据和可选后端契约。

优先级原则：

1. 以 `docs/DESIGN_SYSTEM.md` 为视觉和信息架构契约；新增页面必须先说明主任务与空状态。
2. 每轮改动都能通过 `npm ci && npm run build && npm run test && npm run lint` 验证。
3. 文档、CI、代码现代化同步；不宣传未验证的线上服务。
4. 私密凭据、第三方素材授权与用户数据问题优先于新页面。

## 2.1 v0.4.0 — 离线馆藏与声景曲库（当前版本）

| 优先级 | 事项 | 为什么 | 验收标准 |
| --- | --- | --- | --- |
| P0 | 离线诗词馆藏 | 旧演示数据太少，且首页随机句 API 不应承担业务诗库 | 16 个固定分卷、9,328 篇上游选段与 22 首精校短章合计 9,350 篇；分卷、清单与哈希可复现校验，首包保持轻量 |
| P0 | 默认离线摘录与可选远程源 | 装饰性摘录不应默认依赖第三方接口 | `VITE_POETRY_SOURCE=local` 使用本地摘录；`remote` 失败时回退并标注来源，CI 不依赖外部服务 |
| P1 | 移动端与布局稳定性 | 窄屏筛选、固定播放器、底部导航容易互相遮挡 | 320–1440px 无页面级横向溢出，固定层不交叠，CLS 预算与吸底状态由 Browser E2E 覆盖 |
| P1 | 三段可复现本地声景 | 单段 8 秒演示音缺少真实播放体验 | `npm run audio:generate` / `audio:verify`、播放列表、切轨、进度、音量、偏好记忆与错误重试可用且默认离线 |
| P1 | 保存发布口径 | 公开描述仍停留 27 项单测与 v0.3.0 | README、Release notes、欢迎帖、宣发草稿、About 与 issue 按 39 项单测和 v0.4.0 实际状态更新 |
| P2 | 跨浏览器 / 视觉回归 | 当前 CI 只覆盖 Chromium CDP 关键路径 | 后续补 Firefox/WebKit 与截图基线；本版本不以多浏览器矩阵冒充已完成 |
| P2 | 素材授权核验 | 哈希只是身份证据 | 继续保留 #4 为真实未完成项；无法确认的历史字体/图片/favicon 不写成已获授权 |

## 4. v0.5.x — 可选后端与社区协作

- 只有当维护者确认边界后，才增加示例 API / Docker Compose / 账号与创作持久化；保持前端仓库独立运行。
- 讨论隐私说明、数据导出与关闭线上服务的方式；不把演示账号系统当生产认证。
- 建立贡献者名录、定期议题与可视化维护记录，但不设置增长目标或 SLA。

## 5. v1.0 之后 — 社区化（条件性）

只有在工程优化、E2E、错误态与素材授权问题稳定后，才考虑：

- 公开且被维护者验证的静态前端 Demo（仅演示数据，不收集账号）；
- 可插拔后端、账号与创作持久化，带隐私说明与数据导出；
- 完整中英文 i18n、主题与阅读偏好；
- Discussions 定期议题、贡献者名录、Release 自动化、可视化仪表盘；
- 与其他中文开源诗词语料/工具的可授权集成。

任何一个「线上」能力都必须先回答：谁托管、谁维护、数据从哪来、如何关闭、如何回滚、出问题向谁报告。没有答案就不写进 README 的特性承诺。

## 6. 明确不做的事

- 不恢复旧 MemFire/Vercel 展示地址为官方 Demo。
- 不在没有授权审查前把自定义音源、第三方字体/诗词全文宣称为 MIT 内容。
- 不为了 star 数、曝光或版本号制造虚假数据、刷量或夸大功能。
- 不把本仓库变成需要付费/私密基础设施才能运行的项目。
- 不把 GitHub 发布、Pages 或外部宣发写成未经核对的事实。

## 7. 每次迭代的 Definition of Done

- [ ] 改动范围写入 `CHANGELOG.md` 的对应版本或 `Unreleased`。
- [ ] `README.md`、`docs/DEVELOPMENT.md`、`docs/DEPLOYMENT.md` 与实际脚本/变量一致。
- [ ] CI 在 Node 20/22 执行 `npm ci`、build、测试、构建冒烟，Documentation checks 执行静态扫描与文档检查，Browser E2E 执行 CDP 关键路径。
- [ ] 无新增硬编码密钥、真实用户数据或失效线上承诺。
- [ ] 至少一条手动 QA 路径被记录；失败路径也有说明。
- [ ] 若发布，Release notes 只描述已合并并验证的内容。
