# 路线图

> 路线图是公开优先级与验收思路，不是发布日期、商业承诺或维护者 SLA。最后更新：2026-11-07。v0.2.0 已完成现代化；当前 `v0.3.0` 候选已完成视图层重构、静态资源收敛、CI Browser E2E 与不可达音源状态。

## 0. 当前判断

兰泽诗词最有价值的部分是中文诗词内容、素材和完整 `git` 历史。当前 `main` 已把界面收敛到「一首诗一展厅」的六页面结构，移除旧 UI 套件与占位栏目；接下来的重点是视觉回归、素材授权、内容依据和可选后端契约。

优先级原则：

1. 以 `docs/DESIGN_SYSTEM.md` 为视觉和信息架构契约；新增页面必须先说明主任务与空状态。
2. 每轮改动都能通过 `npm ci && npm run build && npm run test && npm run lint` 验证。
3. 文档、CI、代码现代化同步；不宣传未验证的线上服务。
4. 私密凭据、第三方素材授权与用户数据问题优先于新页面。

## 1. v0.2.0 — 本地可运行的开源前端（已完成）

## 2. v0.3.0 — 青瓷数字诗馆（候选）

> 当前 `main` 已完成下列工程事项；发布前以 CI、Browser E2E 与本地验证为准，不把候选写成已发布 Release。

| 优先级 | 事项 | 为什么 | 验收标准 |
| --- | --- | --- | --- |
| P0 | 视图层与信息架构重构 | 旧页面与 UI 套件难以维护，阅读主任务不清晰 | 六类页面、自有组件、历史单张摘录卡例外、旧 URL 重定向；27 项单测与构建通过 |
| P0 | CI 可复现的浏览器 E2E | 本机 Chrome 冒烟无法约束每次 `main` 提交 | `.github/workflows/browser-e2e.yml` 安装 Chromium，执行 CDP 桌面/窄屏、搜索、收藏、登录与发布链路 |
| P0 | 静态资源与布局稳定性 | 历史大字体/图片与模糊尺寸造成体积和布局抖动 | WOFF2 子集、压缩展品图、显式尺寸、CLS 预算 0.05、无 `backdrop-filter` |
| P1 | 不可达自定义音源的状态 | 无效配置已有回退提示，但 URL 不可达缺少可见状态 | 播放器显示「音源不可达」并允许重试，业务功能不白屏；`role="status"` 可读取 |
| P1 | 素材哈希与来源线索 | WOFF2 子集与压缩展品图派生自历史素材 | `docs/THIRD_PARTY_ASSETS.md` 记录当前二进制 SHA-256；授权本身仍标为未核验 |
| P1 | 核验优化后素材的授权 | 哈希不是授权证明 | 补齐来源/许可；无法确认时替换为授权明确的字体与图像 |
| P1 | 跨浏览器 / 视觉回归 | 当前 CI 只覆盖 Chromium CDP 关键路径 | 后续补 Firefox/WebKit 与截图基线，不与 Chromium 冒烟混为一谈 |
| P1 | 完善加载 / 空 / 错误 / 成功四态 | 六类主页面已有基础状态，仍需跨浏览器复核 | 主要页面无无限 loading、无白屏；错误可复制报告 |
| P2 | 清理旧兼容路由 | 旧 URL 目前统一重定向 | 保留至少一个发布周期后逐步移除无访问记录的重定向 |
| P2 | `package.json` 增加 `engines` | 明示支持版本并避免命令猜测 | Node 20/22 与 CI、文档一致 |

## 4. v0.5.x — 可选后端与社区协作

- 只有当维护者确认边界后，才增加示例 API / Docker Compose / 账号与创作持久化；保持前端仓库独立运行。
- 讨论隐私说明、数据导出与关闭线上服务的方式；不把演示账号系统当生产认证。
- 建立贡献者名录、定期议题与可视化维护记录，但不设置增长目标或 SLA。

## 5. v1.0 之后 — 社区化（条件性）

只有在工程优化、E2E、错误态与素材授权问题稳定后，才考虑：

- 公开且被维护者验证的静态前端 Demo（仅演示数据，不收集账号）；
- 可插拔后端、账号与创作持久化，带隐私说明与数据导出；
- 完整中英文 i18n、主题与阅读偏好；
- Discussions 定期议题、贡献者名录、Release 自动化、可视化仪表盘；
- 与其他中文开源诗词语料/工具的可授权集成。

任何一个「线上」能力都必须先回答：谁托管、谁维护、数据从哪来、如何关闭、如何回滚、出问题向谁报告。没有答案就不写进 README 的特性承诺。

## 6. 明确不做的事

- 不恢复旧 MemFire/Vercel 展示地址为官方 Demo。
- 不在没有授权审查前把自定义音源、第三方字体/诗词全文宣称为 MIT 内容。
- 不为了 star 数、曝光或版本号制造虚假数据、刷量或夸大功能。
- 不把本仓库变成需要付费/私密基础设施才能运行的项目。
- 不把 GitHub 发布、Pages 或外部宣发写成未经核对的事实。

## 7. 每次迭代的 Definition of Done

- [ ] 改动范围写入 `CHANGELOG.md` 的对应版本或 `Unreleased`。
- [ ] `README.md`、`docs/DEVELOPMENT.md`、`docs/DEPLOYMENT.md` 与实际脚本/变量一致。
- [ ] CI 在 Node 20/22 执行 `npm ci`、build、测试、构建冒烟，Documentation checks 执行静态扫描与文档检查，Browser E2E 执行 CDP 关键路径。
- [ ] 无新增硬编码密钥、真实用户数据或失效线上承诺。
- [ ] 至少一条手动 QA 路径被记录；失败路径也有说明。
- [ ] 若发布，Release notes 只描述已合并并验证的内容。
